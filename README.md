# 就活コンパス

**企業の比較から日程調整まで、自分の就職活動を一か所で把握するためのWebアプリケーションです。**

企業・選考状況・説明会ノート・応募タスク・スケジュール・紹介元のエージェントを関連付けて管理します。自身の就職活動で感じた不便を出発点に、実際に使いながら機能とデータ保護の仕組みを改善しています。

## 開発の背景

就職活動では、企業について調べることに加えて、説明会の記録、選考状況の確認、提出物の管理、面接の日程調整など、多くの情報を扱います。複数の就活エージェントを利用すると、「この企業は誰から紹介されたのか」も追いにくくなります。

開発のきっかけは、次のような自身の困りごとでした。

- 説明会で聞いた内容や、そのとき感じた魅力・疑問を残して、あとから企業を比較したい。
- 各企業の選考がどこまで進んでいるか、何を優先すべきかを一目で把握したい。
- 説明会や面接の予定が増えると、登録・確認だけでなく、空いている候補日を探すことにも手間がかかる。
- 複数のエージェントから紹介された企業と、紹介元との対応を整理したい。
- 企業の概要を確認するたびに、企業名で検索し直す手間を減らしたい。

そこで、単に企業名や予定を一覧にするだけでなく、**「企業について知る → 比較する → 応募・選考を進める → 次の日程を決める」までをつなげて管理する**ことを目指しました。

## 課題をどう機能にしたか

| 利用時の課題 | 実装した機能 |
| --- | --- |
| 選考状況や志望度を把握しづらい | 企業一覧・選考ボード、志望度スコア順の表示、応募カテゴリによる整理 |
| 説明会前と説明会後では、同じ志望度でも判断の根拠が違う | 「説明会前・説明会後・未設定」の判断段階を保存 |
| 説明会の記録をあとから読み返しにくい | 閲覧用プレビューと、AIによる見出し・箇条書きへの再構成 |
| SPIや履歴書などの提出・受験期限を忘れそうになる | 企業・エージェントに紐づくタスク、締切日・時刻、完了状態の管理 |
| 学校やアルバイトを含めて空いている日を探すのが大変 | 固定予定と例外日を反映した、期間指定の空き時間検索 |
| 仮の日程が確定後も残り、予定を整理し直す必要がある | 仮予定の表示と、確定時の他候補の自動取り消し |
| 紹介元のエージェントが分からなくなる | 企業とエージェントの関連付け、エージェント面談の登録 |
| 共有相手に編集権限を渡さず、状況だけ伝えたい | 企業一覧・予定・空き時間の共有用PNG画像を作成 |

## 主な機能

### 企業・選考管理

企業名、業種、企業概要、公式URL、選考状況、紹介元をまとめて保存します。

志望度は高中低の評価に加えて、任意の0〜100点のスコアを設定できます。「確実に受けたい」「練習として受けたい」「まだ分からない」などの応募カテゴリでも整理でき、志望度順・カテゴリ別の画面から評価を直接変更できます。

自社開発・SIer・SESなどの事業形態は複数選択に対応し、主力の形態を区別して表示します。企業一覧は志望度スコア順を既定とし、見送り・辞退の企業は通常非表示、表示する場合も末尾に配置します。

### スケジュールと日程調整

- 企業の選考、エージェント面談、個人の予定、複数日にわたる終日予定を登録。
- 一次選考・二次選考・最終選考などの定型ボタンで予定名を入力。
- 学校の時間割やアルバイトの固定シフトを登録し、その日だけの変更にも対応。
- 土日祝を区別し、学校の通常の時間割は土日祝を除外。休暇・振替日も設定可能。
- 日本時間の9:00〜20:00を対象に、必要な時間と予定前後の余裕を指定して候補日を検索。

仮予定には「(仮)」を付け、確定予定と区別します。通常は企業・エージェントごとに候補を自動でまとめるため、グループの設定は不要です。別の選考などを分けたい場合だけ、任意のグループを指定できます。

保存済みの仮予定を確定すると、画面に示した同じグループの他候補をごみ箱へ移動します。以前の確定予定や別グループの予定は変更しません。個人の予定は自動でまとめず、必要な場合にグループを指定します。

### 説明会ノートとAI支援

聞いた内容、感想、企業への印象を記録し、まず閲覧用プレビューで確認できます。

Geminiによる文章整理は、誤字や語尾の修正だけでなく、後日読み返しやすい構成への再整理を目的としています。AIの案は原文と比較してから採用でき、生成に失敗した場合も原文を変更しません。

企業概要の取得では、Tavilyで公式サイト候補を探し、取得したページ本文をGeminiで要約します。公式URLを指定することもでき、候補の所在地や参照元を確認してから採用する流れにしています。

### 情報共有とChatGPT連携

共有用の画像は、対象企業や期間、載せる項目を選んでプレビューし、PNGとして保存できます。アプリが相手へ自動送信することはありません。

また、MCPによる読み取り専用のChatGPT連携を実装しています。連携は既定で無効で、利用者が参照を許可する記録の種類や、除外する記録を設定します。連携経由の書き込み・削除はできません。

## 実際の利用から重視するようになったこと

### 入力や保存済みデータを失わないための設計

開発途中に、ノート作成中に入力欄の外を押すと、それまでの入力が失われる問題が見つかりました。就職活動の記録を預けるアプリでは、使いやすさだけでなく、入力の保全と復元手段が重要だと捉え、保存まわりを改善しました。

- **入力中の保護**：入力操作時に端末へ下書きを保存し、クラウドにも同期。編集画面の枠外を押しても閉じないようにしています。
- **閉じる操作の明示**：編集を続ける、下書きを残す、今回の下書きを削除する、を選択できます。保存済みの記録は変更しません。
- **同時編集の保護**：版番号を照合し、古い画面の内容で新しい記録を上書きしないようにしています。
- **変更履歴とごみ箱**：更新前の内容を残し、削除した記録も復元できるようにしています。
- **候補確定の整合性**：確定と他候補の取り消しをまとめて処理し、候補の変更や保存失敗があれば更新を止めます。
- **バックアップ**：保存済みデータをgzip圧縮したJSONとして保存。Windows向けの定期バックアップは、保存容量の上限を2GiBとし、正常な世代を残す仕組みです。

保存済みの記録には保存期限を設けず、下書き・履歴・ごみ箱の本文には暦の1か月の保存期限を設けています。バックアップからの一括復元は、既存データを上書きせず、企業などの関連付けを維持して追加します。

これらはデータ損失や意図しない変更のリスクを下げるための対策であり、端末故障や外部サービス障害を含むあらゆる状況での完全な保全を保証するものではありません。

### 操作の手間と誤操作の防止を両立する

使いながら「設定できること」と「普段の操作で設定を要求すること」を分けて考えるようになりました。

例えば、仮予定は当初グループを手動で設定する方式でしたが、通常は同じ企業で複数の選考日程を並行して調整しないため、企業・エージェント単位の自動判定を基本に変更しました。一方で、例外的な使い方に備え、任意のグループ指定は残しています。

### AIの出力をそのまま保存しない

企業概要の誤取得や、ノート整理時の外部APIエラーも、実際の利用で見つかった改善点です。参照元の確認、原文と生成案の比較、失敗時の入力保持を組み込み、利用者が確認してから記録へ反映する設計にしています。

## 技術構成

| 領域 | 使用技術・構成 |
| --- | --- |
| UI | React 19、TypeScript、Tailwind CSS、Radix UI系コンポーネント |
| アプリケーション | Next.js App Router形式の構成をVinext / Viteで実行・ビルド |
| 実行環境・保存 | Sites、Cloudflare Workers、Cloudflare D1 |
| スキーマ・入力検証 | Drizzle ORM / マイグレーション、Zod |
| AIによる文章整理・要約 | Gemini API |
| 公式サイトの検索・本文取得 | Tavily API |
| 外部からの参照 | MCPによる読み取り専用ツール |
| バックアップ | gzip圧縮JSON、Windows向け定期実行 |

データは所有者ごとに取得・更新範囲を制限しています。APIキーはサーバー側の秘密設定で管理し、ソースコードやブラウザーへ含めない構成です。

## 開発の進め方

個人開発として、日々の就職活動で見つかった課題をもとに仕様を決め、実際に利用して改善を繰り返しています。実装・調査・検証には生成AI（ChatGPT / Codex）を活用しています。

特に保存処理では、正常に保存できることだけでなく、同時編集、通信失敗、再試行、削除・復元、他の利用者のデータとの分離などを検証対象にしています。

- [データ保護の検証](verify-data-safety.mjs)：版番号の競合、更新失敗時の整合性、下書き、復元、自動候補グループなど。
- [ChatGPT連携の検証](verify-chatgpt.mjs)：認証、参照範囲、除外設定、読み取り専用の制約など。
- [企業評価の検証](verify-company-interest.mjs)：志望度の並び順、見送り・辞退の扱い、企業属性など。
- [共有画像の検証](verify-share-images.mjs)：公開項目の制限、選択企業、非公開予定の扱いなど。

## 閲覧について・現在の制約

本番環境には個人の就職活動の記録を保存しているため、アクセスを制限しています。一般公開のデモではありません。

- Google Calendarなどの外部カレンダーとは未連携です。空き時間検索はアプリ内に登録された予定を対象とします。
- AI機能と公式サイト検索は外部APIの利用可否・制限に影響を受けます。企業の同定や要約内容の最終確認は利用者が行います。
- 定期ローカルバックアップはWindows向けで、実行環境と接続情報の個別設定が必要です。
- 検証スクリプトの成功と、すべての端末・ブラウザーでの動作確認は区別しています。最新の実装・確認状況は [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) に記録しています。

### ローカル起動

前提はNode.js 22.13.0以上とnpmです。Sites向けの実行構成を含むリポジトリです。

```sh
npm run install:ci
npm run dev
```

ローカル開発サーバーは通常 `http://127.0.0.1:5173/` で起動します。ローカルの認証・保存領域と本番のデータは別で、ローカル動作確認用データは公開先に含まれません。

### 外部APIと本番環境

- `GEMINI_API_KEY`：ノート整理・企業概要の要約に使用。
- `TAVILY_API_KEY`：公式サイト候補の検索・本文抽出に使用。
- `GEMINI_MODEL`：企業概要の要約に渡す任意設定。ノート整理のモデル選択は [lib/proofread.ts](lib/proofread.ts) で別途管理しています。

`.env.gemini` などのローカルファイルはGitの管理対象外で、本番の秘密設定へ自動反映されるものではありません。本番でAPI機能を使う場合は実行環境側へ設定し、再デプロイします。既存サイトの識別子・認証・データベース設定を含むため、別環境へ公開する場合は、その環境用の構成を用意してください。

### ビルドと検証

```sh
npm run build
node node_modules/typescript/bin/tsc --noEmit
node verify-data-safety.mjs
node verify-chatgpt.mjs
node verify-widget.mjs

node verify-share-images.mjs
```

D1のスキーマ変更時は `npm run db:generate` でマイグレーションを生成します。バックアップの運用・復元方法は [local-backup/README.md](local-backup/README.md) を参照してください。

## iPhoneのホーム画面で予定を確認

Scriptableを使い、今後7日間の予定と未完了タスクの期限をホーム画面に表示できます。アプリの「iPhoneウィジェット」でコードをコピーし、専用の接続キーを発行します。Windowsで開発・配信でき、Macやパソコンの常時起動は不要です。

アプリ自体は非公開のまま、Cloudflare Workersの読み取り専用中継が必要な情報だけを返します。キーは再発行・停止でき、ノート本文や下書きは共有しません。更新間隔はiOSに依存します。構成・導入・運用の詳細は [widget-relay/README.md](widget-relay/README.md) を参照してください。
